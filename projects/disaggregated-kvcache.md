## 一句话

把 LLM 推理中的 KV cache 从计算实例中解耦出来，独立地调度、存储与传输，以提升吞吐、降低尾延迟并支持跨请求复用。

## 背景与动机

- 长上下文与高并发下，KV cache 占用显存成为主要瓶颈。
- prefill（算力密集）与 decode（带宽 / 容量密集）资源特征不同，混部会互相干扰。
- 前缀复用、多轮对话与跨请求共享带来 cache 迁移与复用需求。
- 内存层级（HBM → 主机内存 → 远端内存 / SSD）为容量扩展提供空间，但引入传输开销。

## 目标与非目标

**目标**

- 明确解耦架构的收益边界：什么负载、模型规模、上下文长度下划算。
- 量化传输路径（NVLink / RDMA / TCP）与调度策略对 TTFT / TPOT 的影响。

**非目标**

- 不涉及训练侧优化；不修改模型结构。

## 关键问题

1. prefill / decode 解耦后，P:D 实例比例如何随负载自适应？
2. KV cache 放在哪一层（HBM / 主机内存 / 远端内存 / SSD）？淘汰与预取策略如何设计？
3. 传输路径对 TTFT / TPOT 的贡献如何分解？什么时候传输成为瓶颈？
4. 如何与 continuous batching、前缀缓存协同，而不是互相抵消收益？

## 方案草案

- 分层：调度器 / cache 管理器 / 传输层 / 存储后端，各自独立演进。
- 关键指标：TTFT、TPOT、吞吐、cache 命中率、传输开销占比、显存碎片率。
- 先做 baseline：单机混部 vs 单机手动分离，确认收益方向。
