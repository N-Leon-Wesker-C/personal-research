# README · 工作流手册

> 这份文档定义这个仓库怎么用。规则可以改，但先改这里，再改习惯。

## 一分钟版本

新信息进 [INBOX](INBOX.md) → 每天从 [TASKS](TASKS.md) 选 1–3 件事 → 晚上写 daily → 每周固定 45 分钟清空 INBOX、更新索引、写 weekly。其余时间只做研究，不做整理。

## 这是什么

`personal-research/` 是一个「捕获 → 整理 → 研究 → 复盘」的个人研究工作台，不是日记，也不是书签仓库。它只服务两个目标：

1. 任何信息不在脑子里丢失。
2. 任何研究想法都有路径走到可验证的实验。

入口是 [HOME.md](HOME.md)；本文件是详细操作手册。

## 五条核心原则

1. **先捕获，后整理** —— 新信息只进 INBOX，不现场分类。
2. **每条信息只有一个家** —— 任务、知识、问题、项目、复盘，选一个。
3. **索引优先** —— 没被索引链接的笔记等于不存在。
4. **当前承诺要少** —— TASKS 保持短，长期愿望放 RESEARCH。
5. **定期删除** —— 两周没动的条目默认删掉，而不是继续囤。

## 文件职责

| 文件 / 目录 | 只放什么 | 不放什么 |
| --- | --- | --- |
| INBOX.md | 未处理的原始捕获 | 已分类内容、长期笔记 |
| TASKS.md | 当前承诺（≤10 条） | 愿望清单、研究问题 |
| KNOWLEDGE.md | 主题索引、阅读清单 | 笔记正文 |
| knowledge/*.md | 按主题聚合的长期知识 | 项目进展、待办 |
| RESEARCH.md | 研究问题、idea 索引、状态 | 具体实验记录 |
| research/ideas/*.md | 单个 idea 的展开 | 已立项项目的细节 |
| projects/*.md | 项目目标、决策、实验、里程碑 | 通用知识 |
| REVIEWS/daily/ | 当天日志与反思 | 长期知识 |
| REVIEWS/weekly/ | 周复盘与下周计划 | 日常流水账 |
| HOME.md | 导航与一分钟流程 | 详细规则（放这里） |

## 信息分流

每处理一条 INBOX，只问一个问题：**它接下来要变成什么？**

| 它的性质 | 去哪里 | 动作 |
| --- | --- | --- |
| 要做的事 | TASKS.md | 写成动词开头的下一步 |
| 事实、概念、论文结论 | knowledge/<主题>.md | 追加笔记 + 更新 KNOWLEDGE 索引 |
| 值得回答的问题 | RESEARCH.md | 加一行问题，标「开放」 |
| 想做的方案 / 猜想 | RESEARCH.md idea 池，或 research/ideas/ | 一句话 → 展开 |
| 项目决策 / 实验 / 进展 | projects/<项目>.md | 记入决策日志 / 实验表 |
| 当天的感受与反思 | REVIEWS/daily/ | 写进当天日志 |
| 两周内不会用、也说不出用途 | 删除 | 不保留 |

**默认规则：拿不准就先留在 INBOX，周末统一处理。** 不要为了「整理」把信息搬来搬去。

## 节奏

| 时机 | 时长 | 动作 |
| --- | --- | --- |
| 随时 | 30 秒 | 新信息写进 INBOX，一条一行 |
| 每天 | 10 分钟 | 早上从 TASKS 选 1–3 件事；晚上写 daily |
| 每周 | 30–45 分钟 | 清空 INBOX、更新索引、复盘、定下周焦点 |
| 每月 | 20 分钟 | 清理僵尸任务、暂停/结束项目、整理阅读清单 |

固定一个每周复盘时间（例如周日晚），写进日历。没有固定时间，这套系统一周内就会失效。

## 每天

**早上（3 分钟）**

1. 打开 TASKS.md，只看「进行中」和「下一步」。
2. 选 1–3 件今天真正能推进的事，其他一律不碰。
3. 如果今天的任务不清楚，说明昨天没写「明天第一件事」，现在补。

**白天**

- 任何新信息 → INBOX，不中断当前工作。
- 项目有决策或实验结果 → 当场写进项目页，哪怕只有一行。

**晚上（7 分钟）**

1. 写 `REVIEWS/daily/YYYY-MM-DD.md`（模板见下）。
2. 把当天完成的任务勾掉。
3. 有明确去向的 INBOX 条目可以顺手分流；拿不准的留给周末。
4. 写下明天第一件事。

## 每周（核心维护时段）

建议固定 30–45 分钟，按顺序做：

1. **清空 INBOX** —— 逐条分流或删除，目标清空；超过两周的条目直接删。
2. **同步 TASKS** —— 完成项归档；两周未动且不重要的删除；重要的拆成更小的下一步。
3. **沉淀知识** —— 把本周读到的结论写进对应主题笔记，更新 KNOWLEDGE.md 的索引和日期。
4. **推进研究** —— 检查 RESEARCH.md 中每个问题的状态；有新结论就更新「下一步」。
5. **更新项目** —— 检查每个 active 项目的里程碑、决策日志、实验表。
6. **写周复盘** —— `REVIEWS/weekly/YYYY-Www.md`，确定下周唯一最重要的事。
7. **看一眼目录** —— 有没有文件放错位置；没有索引的笔记补链接。

## 知识笔记怎么写

统一格式，新笔记放在「笔记」区最上面：

```markdown
### 2026-10-28 · 标题

- 来源：论文 / 博客 / 对话 / 实验
- 要点：用自己的话写，不抄原文
- 我的判断：可信度、适用边界、和已有认知的关系
- 疑问：还没想清楚的地方
```

规则：

- 一个主题一个文件；不要按论文建文件。
- 一条笔记只回答一个问题。
- 事实、判断、疑问分开写，别混成一段。
- 主题文件超过一屏后，在文件顶部加「目录」。
- 新主题只在「现有四个主题都放不下，且已有至少 3 条相关笔记」时才建，并同步 KNOWLEDGE.md。

## 从问题到项目

研究不是线性流程，但状态要清楚：

```
INBOX 捕获
   ↓
RESEARCH.md 问题（开放）
   ↓
research/ideas/ 展开（探索中）
   ↓  三个问题都能回答
projects/ 立项（进行中）
   ↓
实验 → 结论 → 论文 / 代码 / 复盘
```

立项前必须回答：

1. 要解决的具体问题是什么？
2. 现有方案为什么不够？
3. 最小可验证实验是什么？

三个问题答不上来，就继续留在 idea 池，不要开项目页。

## 项目页怎么维护

- 每个项目一个文件，复制 [projects/project-template.md](projects/project-template.md)。
- 状态只有四种：构思 / 进行中 / 暂停 / 完成。
- 每次做决策，写一行「决策日志」：决策、理由、被放弃的备选。
- 每次实验，写一行「实验与结果」：配置、结果、结论。失败也写。
- 里程碑必须带验收标准，否则不算里程碑。
- 30 天没有任何动作：标「暂停」；连续两个季度没动：归档或删除。

## 防腐烂规则

- INBOX 超过 14 天未处理的条目：删。
- TASKS 超过两周没动：拆小、移回 RESEARCH，或删。
- 项目 30 天无动作：标暂停。
- 没有被 KNOWLEDGE.md 链接的笔记：要么补索引，要么删。
- 不新建顶层目录；现有五个桶足够。
- 不为整理而整理：整理时间每周不超过 45 分钟。

## 第一周上线清单

- [ ] 补全 [projects/bjtuos.md](projects/bjtuos.md) 的定位与目标
- [ ] 在日历上固定每周复盘时间
- [ ] 今天写第一篇 daily
- [ ] 把最近的 5–10 条信息丢进 INBOX，完整走一遍分流
- [ ] 周末完成第一次 weekly，检查 INBOX 是否清空
- [ ] （可选）`git init`，并约定每次周复盘后提交一次

## 常见的错误

- 把 INBOX 当笔记库，越积越多 → 每周必须清空。
- 任务写成名词（「KV cache 调研」）→ 改成下一步动作（「读 DistServe 并记 3 条结论」）。
- 收集链接代替阅读 → 阅读清单只放真的会读的。
- 反复调整目录结构 → 结构已经够用，时间花在内容上。
- 项目页只写计划不写结果 → 实验表必须当天填。
